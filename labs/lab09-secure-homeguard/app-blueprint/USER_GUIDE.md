# คู่มือใช้งาน S3 HomeGuard

อัปเดตสำหรับแอป 2.1.3 · [ตั้งค่า](CONFIGURATION.md) · [หลักการทำงาน](../SYSTEM_WORKFLOW.md) · [ปัญหาที่เคยพบ](KNOWN_ISSUES.md)

แอปและ firmware นี้เป็นชุด development สำหรับเรียน รุ่นที่มีผลจริงจับคู่ **BLE** และสั่ง GPIO บนบอร์ดเปล่าได้แล้ว ส่วน SoftAP/migration และ production hardening ยังต้องตรวจครบตาม [รายงาน](../TEST_REPORT.md)

> คู่มือนี้ระบุพฤติกรรมเป้าหมายเทียบแอปผู้สอน ผู้เรียนต้องสร้างแอปและ firmware ของตนก่อนตามสเปก ไม่ใช่คู่มือ APK พื้นฐาน Lab07 ที่แจกดาวน์โหลด และไม่มี source/secure APK สำเร็จของ Lab09 ให้ติดตั้งจาก repository สาธารณะ

## 1. เมนูหลัก

| เมนู | ใช้ทำอะไร |
|---|---|
| หน้าหลัก | ดูบอร์ดที่เลือก ยืนยันตัวตน แล้วควบคุม Relay 1/2 |
| อุปกรณ์ | เลือกบอร์ดที่จะเปิด Dashboard |
| + ตรงกลาง | เพิ่มและจับคู่บอร์ด |
| ประวัติ | ดูเหตุการณ์ที่แอปบันทึก เป็นรหัสสถานะที่ไม่ใส่ secret |
| ตั้งค่า | จัดการอุปกรณ์, MQTT Broker และความปลอดภัย |

เมนูใช้ Compact Center: ปุ่ม + อยู่กลาง แท็บเปลี่ยนสีไอคอน/ชื่อ ไม่มีเงาหรือวงกลมไฮไลต์ตามแท็บ เมื่อ source ที่ build เปิดโหมดเต็มจอ ให้ปัดจากขอบจอเพื่อเรียกแถบ Android ชั่วคราว

## 2. ตรวจโทรศัพท์ก่อนจับคู่

1. ติดตั้ง APK ที่ตรง architecture ตาม [BUILD_GUIDE](BUILD_GUIDE.md)
2. ตั้งล็อกหน้าจอโทรศัพท์ เปิด Bluetooth และอนุญาตสิทธิ์ตามหน้าต่าง Android
3. ไป **ตั้งค่า → ความปลอดภัย → ทดสอบ crypto ในโทรศัพท์** ต้องผ่านรายการที่แสดง รวม SRP packet ใน Release APK
4. ไป **ตั้งค่า → MQTT Broker** เลือกโปรไฟล์และกดทดสอบ ผลผ่านขั้นนี้ยังไม่เปิดรีเลย์
5. บอร์ดต้องใช้ development firmware `lab09_s3_homeguard` และโหมดโมดูลตรงของจริง

## 3. จับคู่ผ่าน BLE

1. เข้าเมนู **+** กรอกชื่อ, Wi-Fi ของบอร์ด และเลือก Broker ก่อน เพื่อเหลือเวลากรอกรหัสท้องถิ่น
2. ที่ Serial Monitor 115200 เลือก `transport ble` สำหรับหน้าต่างถัดไป
3. กดปุ่มโมดูล OUT18 ค้าง 2 s แล้วปล่อย หรือ BOOT0 สำหรับ bare-board mode รหัสมีอายุในหน้าต่าง 120 s; RESET/EN ใช้รีบูตจึงไม่ใช้แทนปุ่มนี้
4. เลือก BLE แล้วค้นหา `HG_...` ให้ตรงบอร์ด กรอก UUID และ Security2 username/password จากรอบนั้น
5. เลื่อนลงถึงท้ายฟอร์ม กด **จับคู่** แล้วผ่านลายนิ้วมือ/รหัสล็อกจอด้วยตนเอง ไม่ต้องบอกรหัสล็อกจอแก่ผู้ช่วย
6. รอ handshake, ส่งข้อมูล และตรวจ proof จนแอปแจ้งสำเร็จ จากนั้นกลับหน้าหลัก

**ผ่านเมื่อ:** แอปมีรายการบอร์ดและบอร์ดแสดง `paired=1` ไม่ใช้เพียงการค้นพบ BLE หรือการเชื่อม GATT เป็นผลจับคู่สำเร็จ หากหมดเวลาให้ปิดขั้นตอนเดิมแล้วเปิดหน้าต่างใหม่ ใช้รหัสใหม่

## 4. SoftAP เป็นอีก transport ที่ต้องตรวจแยก

เลือก `transport softap` ก่อนกดปุ่มจริง เลือก SoftAP ในฟอร์ม กรอกชื่อ AP/รหัส AP และ Security2 credentials แล้วตอบรับหน้าต่าง Android ที่ให้เชื่อม Wi-Fi ของบอร์ด

ระหว่าง system dialog แอปอาจเข้า pause ระบบต้องหยุด control session และรอแอปกลับ foreground ก่อนทำ SRP/ส่งข้อมูลสำคัญ อย่าออกไปแอปอื่นระหว่างจับคู่ ผล BLE ผ่านใช้แทนผล SoftAP ไม่ได้ ปัจจุบันยังไม่มีผล hardware ครบ workflow ของ SoftAP ในรายงาน

## 5. เปิด Session และสั่งรีเลย์

1. เปิดหน้าหลัก ขณะการ์ดแสดง **แตะเพื่อยืนยัน** ให้แตะการ์ดรีเลย์
2. ผ่านหน้าต่างยืนยันตัวตนของ Android การแตะครั้งนี้เปิด Session ยังไม่ส่ง ON
3. รอ **กำลังยืนยัน → ยืนยันแล้ว** และได้รับ State ของช่องนั้น
4. แตะการ์ดเพื่อสลับ ON/OFF แอปส่งคำสั่งตั้งค่าที่ต้องการ พร้อม request ID/deadline และเข้ารหัส
5. รอผล ACK/State จากบอร์ด เมื่อเกิน timeout แอปขอ State และแสดงไม่ทราบผล ไม่ควรกด ON ซ้ำเพื่อเดาผล

| หน้าจอ | ความหมาย | ทำต่ออย่างไร |
|---|---|---|
| เซสชันล็อก / แตะเพื่อยืนยัน | ยังไม่เปิดสิทธิ์ของรอบนี้ | แตะและยืนยัน |
| กำลังยืนยัน | ต่อ Broker แล้วกำลังตรวจ Session กับบอร์ด | รอ อย่าแตะสั่งซ้ำ |
| ยืนยันแล้ว | ผ่าน application authentication และตรวจความสด | รอ State แล้วควบคุมได้ |
| รอผลจากบอร์ด | มีคำสั่ง pending | รอ ACK/State |
| ยังไม่ทราบผลคำสั่ง | ไม่ได้คำตอบภายในเวลา | ดู State ที่แอปขอใหม่/Serial ไม่ถือว่าคำสั่งไม่เคยทำงาน |
| อุณหภูมิ/ความชื้นเป็นขีด | ไม่มีค่า valid ที่สดพอ | ตรวจโมดูล ไม่ได้หมายถึง MQTT หลุดเสมอ |

สิทธิ์ผู้ใช้มีอายุประมาณ 5 นาที และล็อกเมื่อแอปเข้า background บอร์ดต่อ Lease ชั่วคราวผ่านโทรศัพท์: renew ทุกประมาณ 10 s และหมดอายุ 30 s ปิดแอปจึงอาจไม่ได้ทำให้โหลด OFF ทันที แต่จะมีเงื่อนไข OFF เมื่อขาดการต่ออายุหรือ connection/Session ไม่ครบ

## 6. ตรวจผลที่บอร์ด

พิมพ์ `status` ใน Serial Monitor ในชุด active LOW:

| ผล | แปลว่า |
|---|---|
| `wifi=1 mqtt=1 authenticated=0` | บอร์ดมีทางส่งข้อความ แต่ยังไม่เปิด Session ควบคุม |
| `authenticated=1` | firmware มี Session; แอปยังตรวจสิทธิ์/heartbeat แยกด้วย |
| `gpio16=0` / `gpio16=1` | GPIO16 LOW/ON หรือ HIGH/OFF ตามโหมดนี้ |
| `gpio17=0` / `gpio17=1` | เช่นเดียวกันสำหรับช่อง 2 |

การอ่าน GPIO/State ยังไม่ยืนยันหน้าสัมผัสรีเลย์หรือหลอดไฟจริง หากใช้บอร์ดเปล่าให้รายงานเฉพาะ GPIO

## 7. จัดการ Broker และอุปกรณ์

สร้างโปรไฟล์ใหม่ที่ **ตั้งค่า → MQTT Broker** จากนั้นไป **ตั้งค่า → จัดการอุปกรณ์ → ชื่อบอร์ด → ย้ายไป Broker อื่น** ส่ง candidate ผ่าน local Security2 เปิด Session ผ่าน Broker ใหม่แล้วกดยืนยันภายใน 60 s ต้องอยู่ใกล้บอร์ดและตรวจการย้ายครบสองฝั่ง งานนี้ยังอยู่ในรายการ hardware acceptance ที่ต้องทำเพิ่ม

การลบอุปกรณ์ในโทรศัพท์ลบข้อมูลฝั่งโทรศัพท์ หากจะเพิกถอนเจ้าของบน ESP ต้องทำ physical reset เจ้าของตามคู่มือ: กดค้างประมาณ 10 s หลังตั้งอุปกรณ์ปลอดภัยแล้ว และจับคู่ใหม่ ไม่ทำขั้นตอนนี้เพียงเพื่อทดลองแก้การเชื่อมต่อ

ใน **ตั้งค่า → ความปลอดภัย** มีการคัดลอก public bootstrap config สำหรับเตรียม firmware มี UUID/endpoint/พิน ไม่มี root key และใช้แทนการ provision/flash ไม่ได้ อย่าเพิ่มรหัสผ่านลง export เพื่อให้ตั้งค่าสะดวก

## 8. เมื่อใช้งานติดขัด

| อาการ | สิ่งที่ตรวจ |
|---|---|
| หา action จับคู่ไม่เจอ | เลื่อนท้ายฟอร์ม ปิดคีย์บอร์ด ตรวจว่าปุ่มไม่ถูกเมนูล่างบัง |
| BLE ค้างกำลังเชื่อม | ตรวจ UUID/รอบรหัส/Bluetooth/permission แล้วใช้ขั้น I-01 ใน KNOWN_ISSUES |
| ล้มหลังเริ่มยืนยัน | รัน Release SRP self-test และดูรหัสขั้นที่ผิดก่อนเปลี่ยน Wi-Fi/Broker |
| ทดสอบ Broker ผ่าน แต่ Dashboard ล็อก | ต้องเปิด application Session และมี State จากบอร์ดด้วย |
| ออกจากแอปแล้วกลับมาล็อก | เป็น policy ยืนยันใหม่และรอสถานะรอบใหม่ |
| จับคู่ซ้ำไม่ได้/ค้างหลังปิดหน้าต่าง | ตรวจ lifecycle/timeout และ credential รอบใหม่ ไม่กด RESET ระหว่าง handshake |

ให้จดเวอร์ชันแอป/บอร์ด/transport/ขั้นสุดท้าย/รหัส error โดยไม่แนบรหัสจริง แล้วใช้ [KNOWN_ISSUES](KNOWN_ISSUES.md) และ [test-plan](test-plan.md) ไล่ทีละชั้น
